# Модель входных данных

[Установка](installation.md) · [Примеры](examples.md) · [English](../en/model.md)

Все документы — строгий UTF-8 JSON. Повторные ключи, нечисловые бесконечности,
неизвестные поля схемы и неверные типы отклоняются. Версия — целое число `1`.
Исполняемые примеры в `examples/` служат точным образцом формата.

## Снимок

Верхний объект содержит только `version` и `entities`. Поля каждой сущности:

- `entity_id`: домен и ID в нижнем регистре, например `light.workbench`.
- `hardware_id`: приватный непрозрачный идентификатор устройства.
- `channel`: строковый идентификатор физического канала.
- `role`: уникальное назначение, например `workbench` или `pump_enable`.
- `capabilities`: список уникальных возможностей, например `on_off`.

Пара hardware/channel обозначает физический выход. Entity ID, пары каналов и
роли должны быть уникальны. Диагностике устройства назначьте отдельный канал,
например `rssi`, и свою роль. Роль здесь — планировочная декларация, а не area,
label или device class HA. Программа не проверяет её физическую достоверность.

## Манифест

Поля верхнего уровня: `version`, `snapshot_sha256`, `sources`, `assignments`,
`consumers`. `sources` сопоставляет относительное имя файла с SHA-256.
`assignments` содержит полные новые записи для физических каналов, уже имеющихся
в снимке. Остальные каналы сохраняются. Новое устройство сначала добавляют в
снимок как реально известный запасной канал; скрытого создания железа нет.

Потребитель указывается парой `file` и `pointer` на буквальное строковое значение.
Это RFC 6901: `/` экранируется как `~1`, `~` как `~0`, индексы массива начинаются
с нуля и не имеют ведущих нулей. Каждая обнаруженная ссылка требует политики:

- `follows_role`: найти новое устройство исходной логической роли.
- `follows_hardware`: остаться на исходном физическом канале с новым entity ID.
- `retire`: предложить удаление явно заданного контейнера `retire_scope`.

Для первых двух нужны `kind` (`action`, `display`, `reference`), непустой список
`allowed_roles` и список `required_capabilities`, который может быть пустым.
У `action` обязателен `service_pointer`. Эти ограничения не дают световому
сценарию молча перейти на насос. Расширять их без проверки назначения нельзя.

У retire ровно четыре поля: file, pointer, policy, retire_scope. Область удаления
должна быть объектом-предком ссылки, не корнем документа. В ней допустимы только
ссылки на ту же исходную сущность; смешанные и динамические ссылки блокируют
план. Выбирайте целую устаревшую автоматику, если удаление действия оставит
пустую недопустимую последовательность. Валидатор полной схемы HA здесь не запускается.

## Смена домена

Для перехода light/switch поддержаны простые turn_on, turn_off, toggle и
соответствующие homeassistant-сервисы. Непустые data/data_template требуют ручной
проверки. Общий доменный сервис с несколькими целями автоматически не меняется.
Указанный сервис должен принадлежать действию с этой целью. Для display смена
домена всегда требует проверки функций карточки: switch не наследует яркость.

Лимиты: 2 MiB на файл, 16 MiB всех исходников, 64 файла, 5000 сущностей/назначений/
потребителей, глубина JSON 40, 100000 узлов значений. Идентификаторы — до 256
символов; списки возможностей и допустимых ролей — до 64 уникальных строк.
Файлы обычные, без симлинков; путь источника не может выходить за корень.
