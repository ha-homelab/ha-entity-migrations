# Практические примеры

[Модель](model.md) · [Архитектура](architecture.md) · [English](../en/examples.md)

Все устройства вымышлены. Для точного восстановления примеров выполните
`python3 tools/generate_examples.py`. Ни один пример не подключается к HA.

## Лампа переезжает, старая розетка становится насосной

Команда из README использует `examples/role-swap`. Вначале `plug-a/1` имеет
`light.workbench`, а `plug-b/1` — `switch.spare`. Манифест назначает насосу канал A,
а лампе канал B. Световой сценарий следует роли (`follows_role`) и допускает
только `workbench`. Ссылка остаётся `light.workbench`, хотя физическое устройство
меняется. Отсутствие текстовой замены здесь — правильный результат; новые
привязки показаны в `assignments`.

Устаревший сценарий запасной розетки получает предложение удалить весь объект
`/1`, а не оставить пустой список действий. Программа сама его не удаляет.
При ручном удалении нескольких элементов массива учитывайте сдвиг индексов и
стройте новый план по свежему снимку.

Попробуйте заменить первую политику на `follows_hardware`, сохранив allowed_roles:
план блокируется с `role_not_allowed`. Добавление насоса в разрешённые роли
означает изменение смысла сценария, а не обычное исправление ошибки.

## Light превращается в switch

```sh
ha-entity-migrations --lang ru plan --manifest examples/domain-change/manifest.json --snapshot examples/domain-change/snapshot.json --root examples/domain-change
```

Две правки предлагают заменить цель и сервис light.turn_off. Если добавить
brightness_pct в data, проверить новый исходник и обновить его отпечаток,
получится `service_data_review`. Нужно решить, как должна работать автоматика,
а не просто удалить яркость ради зелёного отчёта.

## Неразрешимый шаблон

Замените каталог на `examples/blocked-template`. Цель формируется Jinja:
программа её не выполняет, возвращает blocked и код 3. Можно представить
проверенную буквальную конфигурацию либо оставить этот фрагмент отдельной
ручной миграцией. Игнорирование кода выхода не делает ссылку разрешённой.

## Изменения исходников

Изменённый без обновления манифеста файл приводит к `stale_source`, снимок —
к `stale_snapshot`. При устаревшей модели кандидатные правки не выдаются.
На одних входных байтах результат детерминирован, кроме выбранного языка.
Файлы остаются неизменными.

Для реального проекта создайте приватные файлы, подтвердите физические каналы,
перечислите потребителей и проверьте результат. В установленном процессе
развёртывания отдельно выполните проверку HA, примените согласованные изменения
и снимите новый read-only снимок. Этот инструмент не выполняет deployment и rollback.
