เอกสารทั้งหมดใช้ JSON UTF-8 แบบเข้มงวด ปฏิเสธคีย์ซ้ำ ตัวเลขไม่จำกัดหรือ NaN และฟิลด์สคีมาที่ไม่รู้จัก ตัวอย่างตรงตัวใน `examples/` เป็นแหล่งอ้างอิงที่รันได้ ฟิลด์เวอร์ชันต้องเป็นจำนวนเต็ม `1` ไม่ใช่สตริงหรือบูลีน

## สแนปช็อต

ออบเจ็กต์บนสุดมีเพียง `version` และ `entities` แต่ละเอนทิตีมีตรงตามนี้:

- `entity_id`: ID โดเมน/ออบเจ็กต์ตัวพิมพ์เล็ก เช่น `light.workbench`
- `hardware_id`: ตัวระบุส่วนตัวที่ไม่ตีความ เลือกโดยผู้ดูแล
- `channel`: ตัวระบุช่องทางกายภาพในรูปสตริง
- `role`: วัตถุประสงค์เชิงตรรกะที่ไม่ซ้ำ เช่น `workbench` หรือ `pump_enable`
- `capabilities`: สตริงไม่ซ้ำที่อธิบายความสามารถ เช่น `on_off`

คู่ฮาร์ดแวร์/ช่องระบุปลายทางกายภาพ ID เอนทิตี ปลายทางกายภาพ และบทบาทเชิงตรรกะต้องไม่ซ้ำในแต่ละกลุ่ม แสดงข้อมูลวินิจฉัยกายภาพเป็นอีกช่อง เช่น `rssi` พร้อมบทบาทเฉพาะของตน บทบาทเป็นป้ายสำหรับวางแผน ไม่ใช่พื้นที่ ป้าย หรือคลาสอุปกรณ์ HA คำประกาศเหล่านี้ไม่ใช่การวัด เครื่องมือจึงตรวจยืนยันกับฮาร์ดแวร์ไม่ได้

## แมนิเฟสต์

ออบเจ็กต์บนสุดมี `version`, `snapshot_sha256`, `sources`, `assignments` และ `consumers` เท่านั้น `sources` จับคู่ชื่อไฟล์สัมพัทธ์กับค่า SHA-256 ส่วน `assignments` มีระเบียนเอนทิตีทดแทนครบถ้วนสำหรับปลายทางกายภาพที่มีในสแนปช็อตแล้ว ปลายทางที่ไม่ได้ระบุจะไม่เปลี่ยน หากเพิ่มอุปกรณ์ใหม่ ต้องใส่ปลายทางสำรองที่สังเกตได้ลงสแนปช็อตก่อน ไม่มีการสร้างหรือลบฮาร์ดแวร์โดยปริยาย และรุ่นนี้ต้องใช้บทบาทไม่ซ้ำ

ผู้ใช้อ้างอิงแต่ละตัวระบุ **ค่าสตริงตรงตัว** ด้วย `file` และ `pointer` ตาม RFC 6901 แปลง `/` เป็น `~1` และ `~` เป็น `~0` ดัชนีรายการเริ่มที่ศูนย์โดยไม่มีศูนย์นำหน้า การอ้างอิงทุกตัวที่พบต้องมีนโยบายชัดเจน:

- `follows_role`: ค้นหาปลายทางที่เป็นเจ้าของบทบาทเชิงตรรกะของต้นทาง
- `follows_hardware`: คงช่องทางกายภาพต้นทางและใช้ ID เอนทิตีใหม่
- `retire`: เสนอให้ลบออบเจ็กต์ `retire_scope` ที่ระบุชัดและมีการอ้างอิงนั้น

ผู้ใช้อ้างอิงที่ไม่เลิกใช้ยังต้องมี `kind` (`action`, `display`, `reference`), `allowed_roles` ที่ไม่ว่าง และ `required_capabilities` ซึ่งว่างได้ การกระทำต้องมี `service_pointer` ข้อจำกัดนี้ป้องกันไม่ให้ใช้ปั๊มที่เปลี่ยนหน้าที่เป็นเป้าหมายแสงสว่าง นี่คือคำประกาศ ไม่ใช่การอนุมานเจตนา

ผู้ใช้อ้างอิงที่เลิกใช้มีสี่ฟิลด์เท่านั้น ได้แก่ file, pointer, policy และ retire_scope ขอบเขตต้องเป็นออบเจ็กต์บรรพบุรุษที่ไม่ใช่ราก และมีได้เฉพาะการอ้างอิงไปยังต้นทางเดียวกันที่เลิกใช้ การอ้างอิงผสมหรือแบบไดนามิกจะบล็อก หากลบการกระทำแล้วเหลือลำดับว่างที่ผิด ให้เลือกทั้งระบบอัตโนมัติเก่า เครื่องมือไม่รันตัวตรวจสคีมา HA

## การเปลี่ยนโดเมน

สำหรับการกระทำข้าม light/switch รองรับเฉพาะ `turn_on`, `turn_off`, `toggle` และบริการ `homeassistant.*` ที่ตรงกัน ไม่รับ `data` หรือ `data_template` ที่ไม่ว่างสำหรับการแปลงบริการอัตโนมัติ บริการเฉพาะโดเมนที่มีหลายเป้าหมายตรงตัวจะถูกบล็อก พอยน์เตอร์บริการต้องเป็นเจ้าของเป้าหมายภายใต้การกระทำของตน การเปลี่ยนโดเมนแสดงผลต้องตรวจคุณลักษณะการ์ดด้วยตนเองเสมอ สวิตช์ไม่อาจรับการควบคุมความสว่างมาเงียบ ๆ

## ขีดจำกัด

2 MiB ต่อไฟล์ แหล่งข้อมูลรวม 16 MiB ไม่เกิน 64 ไฟล์ เอนทิตี การกำหนดค่า หรือผู้ใช้อ้างอิง 5,000 รายการ ความลึก JSON 40 และโหนดค่า 100,000 โหนดต่อไฟล์ ตัวระบุเป็นสตริงไม่ว่างยาวไม่เกิน 256 อักขระ รายการความสามารถ/บทบาทที่อนุญาตมีสตริงไม่ซ้ำได้ 64 ค่า พาธสัมพัทธ์ต้องไม่ขึ้นไปยังโฟลเดอร์แม่ ไม่เป็นพาธสัมบูรณ์ และไม่มีลิงก์สัญลักษณ์ รับเฉพาะไฟล์ปกติ

ตัวโหลดปฏิเสธชื่อแหล่งข้อมูลสองชื่อที่ชี้พาธมาตรฐานเดียวกันหรือเอกลักษณ์ไฟล์เปิดเดียวกัน (อุปกรณ์/inode) รวมตัวคั่นซ้ำ ฮาร์ดลิงก์ และชื่อแทนตัวพิมพ์ใหญ่เล็กบนระบบที่ไม่แยกตัวพิมพ์ ให้คงชื่อเดียวและอัปเดตผู้ใช้อ้างอิง ชื่อแทนไม่สามารถมีนโยบายย้ายต่างกันสำหรับไฟล์กายภาพเดียว ไฟล์อิสระที่เนื้อหาเหมือนกันยังถูกต้อง API บริสุทธิ์ `plan` ไม่เข้าถึงระบบไฟล์ ผู้เรียกที่สร้างแผนผังแหล่งข้อมูลเองต้องบังคับขอบเขตเอกลักษณ์นี้ก่อนเรียก
